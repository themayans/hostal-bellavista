# Hostal Restaurante Bellavista Formentera

A static, multilingual website for the hostal and restaurant on the port of
La Savina, Formentera. **No framework, no runtime dependencies** — every page is
plain HTML generated by a few small Node scripts and committed to the repo.

**Live site:** https://themayans.github.io/hostal-bellavista/
Pushing to `main` rebuilds and redeploys automatically in about a minute.

---

## What replaced what

This site replaces two separate, diverging web presences:

| Old | State | What we took from it |
| --- | --- | --- |
| `bellavista-formentera.com` | WordPress 4.2.39 (2015), no working HTTPS, frozen since 2015 | All the photography, the room and restaurant copy, the three off-site apartments, the ES/EN/DE/IT positioning |
| `hostal-bellavista.com` | Amenitiz platform, Spanish only | The booking engine, the current room taxonomy, the Facebook link |

The old WordPress site also had 14 Lorem Ipsum theme-demo pages publicly
reachable and listed in its XML sitemap (`/prueba-home` and `/portfolio/*`).
Those are **not** carried over.

## How it is built

```
_src/home.html            Master template — the single source of truth for page markup
_src/legal-content.js     Privacy / cookies / legal notice copy, 5 languages
js/i18n.js                ALL site copy in 5 languages + ROOMS, MENU, GALLERY data  ← edit content here
js/main.js                Behaviour + CONFIG (booking engine, contact details)      ← edit settings here
css/styles.css            The whole design system, responsive, print, reduced-motion
scripts/build-home.js     _src/home.html + i18n.js  →  index.html, en|it|de|ca/index.html
scripts/build-legal.js    legal-content.js          →  legal/<doc>/<lang>/index.html  (15 pages)
scripts/build-misc.js     thanks pages, sitemap.xml, robots.txt, llms.txt
scripts/fetch-images.js   One-off: pulled the originals off the old WordPress site
scripts/optimize-images.js  _incoming/*.jpg → assets/images/*.webp, prints a manifest
```

**To change any text, edit `js/i18n.js` and run `npm run build`.** Never edit
`index.html` or the language folders directly — they are generated and your
changes would be overwritten on the next build.

```bash
npm install          # once — installs cheerio + sharp (build tooling only)
npm run build        # regenerates every page, the sitemap, robots.txt and llms.txt
```

### Previewing it locally

```bash
npm start
```

Then open **http://localhost:8091/hostal-bellavista/**. The server prints links
to all five languages and the legal pages when it starts. `Ctrl+C` to stop.
Use a different port with `PORT=3000 npm start`.

> Note the `/hostal-bellavista/` in the URL. The generated pages reference their
> assets by absolute path, because that is the base path GitHub Pages serves
> this project from — so a plain static server rooted at `/` would 404 every
> stylesheet and image. `scripts/serve.js` mounts the repo under the same
> prefix, so local preview matches production exactly. After the custom-domain
> cutover that prefix disappears everywhere at once (see DOMAIN-CUTOVER.md).

`docker compose up` also works if you want to run it through Jekyll exactly as
GitHub Pages does (http://localhost:4000/hostal-bellavista/), but it is slower
and you almost never need it — Jekyll does no templating in this project.

### Languages

Five: **Spanish** (source language, served at `/`), English, Italian, German and
Catalan at `/en/`, `/it/`, `/de/`, `/ca/`. Each language is a real, separately
served page with full `hreflang` and `x-default` — not client-side switching.
A first-time visitor landing on the Spanish root is redirected once to their
browser language if we support it; their explicit choice is remembered in
`localStorage` under `bv_lang`.

> **Translation status:** Spanish and English are the primary, carefully written
> versions. Italian, German and Catalan were drafted for launch and deserve a
> native read-through before any printed or paid campaign points at them.
> The old site's own translation plugin only ever translated the homepage — the
> Spanish subpage copy was all that existed, so these are new translations, not
> migrated ones.

## Features

- **Booking bar** in the hero — date range picker and guest stepper, hand-built,
  no library — that deep-links into the Amenitiz booking engine with the dates
  and party size pre-filled, in the guest's language.
- **Six room and apartment cards** rendered from `ROOMS` in `js/i18n.js`, each
  with capacity, bed configuration, view and a direct booking link.
- **Restaurant menu**, tabbed by course, rendered from `MENU`.
- **Masonry gallery** with a keyboard-navigable lightbox, captions, and explicit
  image dimensions so nothing shifts as photos load.
- **Enquiry form** via FormSubmit — no backend, honeypot, captcha, and the
  chosen dates carried into the email.
- **schema.org** `Hotel` + `Restaurant` graph, Open Graph and Twitter cards with
  a real `og:image` (the old site had none, so shared links rendered blank).
- **Legal pages** — privacy, cookies and *aviso legal* in all five languages.
- **`llms.txt`** — a plain-English fact sheet so AI assistants answer questions
  about the property from our facts rather than stale directory listings.
- Accessible by construction: skip link, visible focus rings, real labels,
  `prefers-reduced-motion` support, and a print stylesheet.
- **No cookies, no analytics, no trackers** — which is why there is no consent
  banner. The only browser storage is the language preference.

## Deployment

GitHub Actions (`.github/workflows/pages.yml`) builds with
`actions/jekyll-build-pages` and deploys with `actions/deploy-pages`. Jekyll
does no templating here — every page is already generated — it just copies the
tree and drops the tooling listed in `_config.yml`'s `exclude`.

To move to `bellavista-formentera.com`, see **DOMAIN-CUTOVER.md**.

## Before this goes live

**Read `HANDOVER.md`.** It lists every fact the property has never published
(opening hours, rates, check-in times, policies) and the handful of settings
that need a real value. Nothing on this site is invented — where a fact was
missing, the page says "ask us" rather than guessing, and `HANDOVER.md` tells
you exactly where.
